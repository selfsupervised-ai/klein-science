## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mac Keychain → signing process | The release private key is used in-process only |
| VM build → Mac signature | The Mac signs artifacts the VM built; substitution must be detected |
| signed bundle → Klein lock | Klein will pin the public key as a trust root (one-way) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-42 | Information disclosure | release private key | critical | mitigate | Read only by `security find-generic-password` inside the operator-run, macOS-only sign command. Captured into a zeroised buffer and never printed or logged. Never on the VM or in git (acceptance grep). The operator runs Task 3. |
| T-01-43 | Tampering (wrong bytes signed) | sign | high | mitigate | Signs exactly the JCS bytes klein-rs verifies (manifest to_canonical) with pure Ed25519. Verifies immediately. The byte-flip RED witness uses the real signature. |
| T-01-44 | Spoofing (signature malleability) | verify | high | mitigate | ed25519-dalek =3.0.0 `verify_strict` only, matching klein-rs D-R58. Hex shapes are validated. Tested on the RFC 8032 vectors. |
| T-01-45 | Tampering (artifact substitution between VM and Mac) | sign | high | mitigate | sign refuses unless the Mac's dist --twice component digest equals the VM-published digest (D-07). The linux worker blob is re-hashed from the store. CI's `release verify --artifacts` re-checks digests on every run. |
| T-01-SC | Tampering | ed25519-dalek, cargo-about | high | mitigate | ed25519-dalek exact `=3.0.0` (klein-rs pin; near-name squatters noted). cargo-about pinned and checksummed in plan 01-02. No new PyPI or npm installs. |
</threat_model>
