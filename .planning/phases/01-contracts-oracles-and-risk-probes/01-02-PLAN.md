<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upstream HTTPS → local cache | Third-party bytes (Cyberphone vectors, later TIR/OMR parquet) enter the machine |
| GHCR remote ↔ cache | Private registry; tampering or substitution possible in transit or at rest |
| tool release servers → $CARGO_HOME/bin | Executables that will run with the developer's privileges |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04 | Tampering | store fetch (upstream and remote) | high | mitigate | Recipes pin a sha256 per file. Upstream is https-only (curl --proto =https --tlsv1.2). Every source is re-hashed with sha256_hex before the atomic rename, and a mismatch deletes the partial file and fails. |
| T-01-05 | Information disclosure | registry credentials | high | mitigate | xtask never reads, prints or passes tokens. oras uses the operator's own `oras login` credential store. Commands are logged without the environment. |
| T-01-06 | Tampering | recipe paths and cache paths | medium | mitigate | Recipe `path` must be relative with no `..` and no leading `/`, and is tested by store_recipe_rejects_traversal. Cache names derive only from validated 64-hex digests. |
| T-01-07 | Tampering | host tool binaries | high | mitigate | Every tool has an exact pin. Tarballs are checked against the sha256 approved at the Task 2 blocking-human legitimacy checkpoint. Crates are installed with `cargo install --locked`. |
| T-01-SC | Tampering | cargo installs (clap, toml) and tool installs | high | mitigate | Exact `=` pins, Cargo.lock --locked, and the package-legitimacy blocking-human checkpoint (Task 2) before any [ASSUMED] tool install. |
</threat_model>
