# Phase 1 Plan 02: xtask tooling spine and RFC 8785 vectors Summary

**`cargo xtask` now has one content-addressed store client: a local cache plus an OCI remote through the pinned `oras`, with every transfer re-hashed before the rename. It also has a pinned host-tool table with install and check commands, the klein-rs-aware heavy-job guard, the `check no-corpus` guard and the first `cargo xtask ci`. The RFC 8785 vectors are fetched by recipe against klein-rs's digests, and all six pass against `ksci_wire::to_jcs`.**

## Accomplishments

- **`cargo xtask store`**
  - `fetch <recipe>...` materialises recipe files under `$KSCI_CORPORA/<name>` (default `<target>/corpora/<name>`).
  - `put <file>`, `get <sha256> <out>` and `push <sha256>...`.
  - The fetch order is cache, then remote, then upstream. Every source is re-hashed with `ksci_wire::sha256_hex` before the atomic rename. A blob that fails its digest is deleted, and the error names both digests.
  - Upstream downloads are https-only, including redirects (`--proto =https --proto-redir =https --tlsv1.2`).
  - Recipe paths must be relative with normal components only. Upstream URLs must be `https://`. Digests must be 64 lowercase hex. Duplicate paths are rejected.
- **Remote (D-05)**
  - `KSCI_STORE_REMOTE` defaults to `ghcr.io/selfsupervised-ai/klein-science-store`; `oci-layout:<dir>` is for offline use.
  - `push` checks the descriptor oras reports for each blob: its digest and size must match the local ones.
  - It then pushes the empty config blob, and one OCI image manifest with `artifactType application/vnd.klein-science.store.v1+json` that lists the blobs as `application/octet-stream` layers, tagged `set-<16 hex>`.
  - xtask never reads, prints or passes a token. Authentication is the operator's `oras login`.
- **`cargo xtask tools`**
  - `install`, `check` and `guard -- <cmd>...`.
  - `host::TOOLS` is the single pin table: wasm-tools 1.261.0, cargo-deny 0.20.2, cargo-nextest 0.9.148, cargo-about 0.9.2 (with the `cli` feature), oras 1.3.4, uv 0.13.0, ast-grep 0.45.3 and tree-sitter-cli 0.27.0 (binary `tree-sitter`).
  - The oras and uv tarballs are fetched through `store::fetch_blob` against their approved SHA-256.
  - `tools check` also checks that `rust-analyzer --version` reports the rust-toolchain.toml channel (1.99.0).
  - All 10 rows are `ok` on this Mac.
- **Heavy-job guard (D-04).** `host::heavy_job()`:
  - takes `flock` on `$KSCI_CACHE/heavy.lock`;
  - then polls every 30 s while a `cargo` or `rustc` process with `klein-rs` in its argv is running (the marker is overridable with `KSCI_KLEIN_RS_MARKER`).
  - `host::klein_rs_build_running()` is exposed for plan 01-11.
- **`cargo xtask check no-corpus`.** It runs over `git ls-files --cached --others --exclude-standard` and flags:
  - files over 256 KiB (except `Cargo.lock` and `LICENSE`);
  - payload extensions outside `testdata/`;
  - `testdata/` files over 64 KiB;
  - anything other than `.json` or `.md` under `conformance/golden/`.
- **`cargo xtask ci`.** Under the heavy-job guard it runs `ci::STEPS` in order: tools check, fmt, clippy `-D warnings`, store fetch rfc8785, nextest `--workspace --locked`, and check no-corpus. It stops at the first failure.
- **`conformance/corpora/rfc8785.toml`.** 18 files at Cyberphone `19d51d7f…`. The digests were diffed mechanically against klein-rs `spikes/jcs-parity/fixtures/PROVENANCE.md`: 18 of 18 identical. No vector bytes are in git.
- **`crates/ksci-wire/tests/rfc8785.rs`.** One test per vector (`rfc8785_arrays` … `rfc8785_weird`) checks the JCS bytes against the output file and the outhex rendering. A missing file panics with the fetch command.
  - The upstream output files carry no trailing newline. The test still strips at most one.
  - The outhex files hold 32 space-separated bytes per line, each line ending in `\n`. The test checks that layout exactly.

## Decisions Made

- **Absolute tool paths.** On this Mac `~/.local/bin/uv` (0.12.15) sits ahead of `~/.cargo/bin` on PATH. So xtask runs pinned tools from `$CARGO_HOME/bin` by absolute path, and `tools check` prints a note when PATH resolves a different copy first.
  - Cargo subcommands (nextest, deny, about) are unaffected, because cargo searches `$CARGO_HOME/bin` first.
  - A bare `uv` typed in a shell on this Mac still runs 0.12.15. Later plans must call `host::tool_path("uv")`.
- **Remote fetch streams into the partial file.** oras checks digests itself and fails with a bare "mismatched digest". Streaming its stdout into the partial means the error can still name the expected digest and the digest of the bytes the remote delivered. On success, our own re-hash in `admit` runs as for every other source.
- **Tool tarballs bypass the remote.** They use `fetch_blob` with no remote (cache, then upstream), because oras may not be installed yet when oras itself is fetched.
- **`klein_rs_build_running` is unused for now.** It carries `#[expect(dead_code, reason = "API for plan 01-11's fixed-box manifest")]`, so the attribute fails once plan 01-11 calls it and must then be removed.
- **The outhex check is exact.** The test reproduces the upstream rendering (32 bytes per line, each line ending in `\n`) rather than comparing tokens with whitespace ignored.
