Add publishing as one more verb on the one store client (per D-01, D-05; CONF-02).

1. `StoreCmd::Publish { dry_run }`:
   - collect every 64-hex lowercase value whose JSON key, or TOML key in recipes, ends in `sha256`, from:
     - `conformance/corpora/*.toml`;
     - `conformance/oracles/images.json`;
     - `conformance/golden/*.json`;
     - `conformance/golden/scores/*.json`;
   - deduplicate and sort the digests;
   - for each digest report present-local, present-remote or missing. The remote check runs `oras blob fetch --descriptor` only when not a dry run, or when `--check-remote` is given.

   - Before pushing, refuse unless `oras` reports that it is logged in to the remote registry (`oras repo ls` against the remote's namespace, or a cheap authenticated call). Never read or print the credential.
   - Unit tests (`store_publish_*`) use an oci-layout remote and fixture manifests in a temp dir: collect digests; dry-run lists the present ones; publish pushes only the missing ones; a second publish pushes nothing.
2. Run `cargo xtask store publish --dry-run` on the Mac and record the digest list with local presence in the SUMMARY. Everything produced by plans 01-02 through 01-10 must be present locally in $KSCI_CACHE.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-01-38 | Information disclosure / licence | corpus and golden bytes in GHCR | high | mitigate | The visibility check (`private`) runs before any corpus or golden push and stops on anything else. Only digests referenced by committed manifests are pushed. |

| T-01-SC | Tampering | artifacts in the store | medium | mitigate | Every push and fetch is re-hashed. The set manifests keep blobs referenced. The round-trip fetch from a fresh cache proves integrity end to end. |
